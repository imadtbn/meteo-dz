## الملخص التنفيذي
Meteo DZ تطبيق عربي RTL مبني على React وTypeScript وVite، ويولد صفحات ثابتة لولايات الجزائر الـ58 وصفحات دليل للولايات والعواصم والبحث العالمي والخريطة. الهدف هو تطويره تدريجياً إلى مرصد أطلسي للطقس والمناخ مع الحفاظ على الهوية الحالية والروابط المفهرسة.

## مصادر البيانات وحدود الثقة
| البيانات | المصدر الحالي/المعروف | الضوابط |
|---|---|---|
| الطقس الحالي والساعي واليومي | Open-Meteo Forecast API | وقت التحديث والمنطقة الزمنية وحالة القراءة القديمة |
| الطقس البحري | حقول Marine عند توفرها | عدم استنتاج سلامة البحر أو عرض قيم غير متاحة |
| الولايات والإحداثيات | client/src/data/cities.json | سجل محلي مرجعي ومراجعة الإحداثيات |

| خرائط الأساس | OpenStreetMap | إسناد المصدر ومراعاة سياسة الاستخدام |
| الإنذارات | رابط الديوان الوطني للأرصاد الجوية في التذييل | لم يثبت وجود تغذية آلية رسمية شاملة؛ لا تُستنتج الإنذارات من التوقعات |
| المناخ التاريخي | لم يثبت مصدر موحد في التنفيذ الحالي | لا تنشر بيانات تاريخية دون توثيق المصدر والفترة والترخيص |

التوقعات النموذجية ليست نشرة رسمية. يجب إظهار المصدر والوحدة ووقت التحديث، وتمييز التحذير الرسمي عن التوقع.

## الهوية البصرية
- العربية واتجاه RTL.
- هوية مرصد الأطلس؛ الأزرق #0C5B8C والخلفية #F5F0E6.
- خطوط عربية وعناوين واضحة.
- هيدر وفوتر موحدان عبر PublicChrome.
- بطاقات القراءة الجوية، تصميم متجاوب، ومساحات إعلانية محجوزة.
- لا تغيّر الهوية أو المسارات ولا تسمح بتمرير أفقي بسبب أي توسعة.

## نتائج المراجعة التقنية
1. تضخم HTML: صفحات الولايات المنشورة تجاوزت 360KB في الفحص السابق، مع كتلة Manus runtime مضمنة؛ يجب أن يكون HTML خفيفاً.
2. اعتماد المتصفح على Open-Meteo مباشرة يربط القراءة بتوفر المصدر والاتصال؛ تدرس طبقة API/cache لاحقاً.
3. وجود Express/tRPC/Drizzle لا يعني تشغيلها على استضافة GitHub Pages الثابتة.
4. رابط النشرات الرسمية ليس تغذية آلية موثقة.
5. خريطة الأساس الحالية ليست رادار أمطار أو طبقة أقمار صناعية.
6. الاختبارات الحالية تشمل وحدات وفحوص مخرجات؛ يلزم توسيع اختبارات التكامل والهاتف.
7. يجب قياس Lighthouse وLCP/INP/CLS بعد التعديلات وعدم اعتماد أرقام قديمة كقياس حالي.

## خطة التوسعة — المراحل التسع

### 1. تثبيت البنية والنشر
فصل إضافات التطوير عن الإنتاج، إزالة runtime/debug غير اللازم، فرض حد لحجم HTML، توثيق البنية، واجتياز فحوص الأنواع والاختبارات والبناء.

### 2. طبقة بيانات الطقس
عقد موحد للطقس الحالي والساعي واليومي والبحري، توحيد Forecast وMarine، cache ووقت تحديث وstale، timeouts/retry محدود، وتقييم Cloudflare Worker دون كشف أسرار.

### 3. الرئيسية والتنقل والأداء
الحفاظ على المسارات وSEO، تحميل المكونات الثقيلة عند الحاجة، تحسين الخطوط والصور وJavaScript وتقسيم الحزم، مراجعة الوصول والهاتف والتمرير، وقياس Core Web Vitals.

### 4. مركز الخرائط
فصل الطبقات إلى مكونات مستقلة، إضافة الرياح والحرارة والأمطار من مزود موثوق ومرخص فقط، مع مفتاح طبقة ومفتاح قراءة ووقت تحديث وإسناد، وتحميل عند الطلب.

### 5. الإنذارات الجوية
قناة رسمية قابلة للتحقق أو روابط النشرات الرسمية، سجل يتضمن المصدر والمنطقة والخطورة والإصدار والانتهاء، منع التكرار، وعدم خلط التوقعات بالتحذيرات الرسمية.

### 6. المرصد المناخي
مصادر تاريخية مرخصة وموثقة، تعريف الفترات والوحدات والمنهجية، رسوم شهرية وسنوية حسب الولاية، وتمييز الرصد عن إعادة التحليل والنماذج.

### 7. البحر والزراعة
توسيع البيانات البحرية بعد التحقق من التغطية، مؤشرات الموج والرياح وحرارة المياه، ومؤشرات زراعية جوية موثقة دون تقديم استشارات متخصصة غير مسندة.

### 8. السفر وخدمات المستخدم
مقارنة المدن والطقس على الطرق، حفظ المفضلة محلياً أولاً، بطاقات مشاركة بمصدر ظاهر، Web Push بموافقة المستخدم وبعد بناء مصدر موثوق، ومزامنة الحسابات كخيار لاحق.

### 9. SEO والجودة والإطلاق
صفحات هبوط ذات محتوى فريد، Canonical وsitemap وrobots وSchema، الحفاظ على روابط الولايات، اختبارات المسارات وPWA، اختبار الهاتف والكمبيوتر وفشل الشبكة، وقياس الأداء ومراجعة Search Console.

## تقييم مصادر البيانات والترخيص — مراجعة 2026-11-08

### Open-Meteo: نقطة يجب حسمها قبل زيادة الاستهلاك
الموقع يحتوي على تحميل AdSense، بينما يوضح مزود Open-Meteo أن الخدمة المجانية مخصصة للاستخدام غير التجاري، وأن الاستخدام التجاري يتطلب التواصل/خطة تجارية. بيانات API تحمل CC BY 4.0 مع وجوب الإسناد. لذلك:
- لا نزيد طلبات bulk أو نضيف خرائط كثيفة قبل حسم الترخيص التجاري.
- نراجع الخطة التجارية المناسبة وحجم الاستهلاك المتوقع.
- عند اعتماد API key تجاري، يحفظ في Cloudflare Worker Secret ولا يحقن في Vite أو ملفات المتصفح.
- يستمر إظهار الإسناد: Weather data by Open-Meteo مع رابط الترخيص.
المراجع: https://open-meteo.com/en/pricing وhttps://open-meteo.com/en/features#terms وhttps://creativecommons.org/licenses/by/4.0/

### الرادار: RainViewer غير معتمد حالياً
توثيق RainViewer الحالي يقصر الخدمة المجانية على الاستخدام الشخصي والتعليمي والمجتمعي الصغير، دون SLA، ويطلب إظهار الإسناد. كما أن انتقال 2025/2026 أوقف صور الأقمار الصناعية وnowcast المجاني وحدّ الدقة إلى zoom 7 مع حدود طلبات. لا نعتمد هذه الخدمة لمنصة عامة تتضمن إعلانات دون اتفاق تجاري مكتوب.
المراجع: https://www.rainviewer.com/api.html وhttps://www.rainviewer.com/api/transition-faq.html وhttps://www.rainviewer.com/api/weather-maps-api.html

### الإنذارات: ONM هو المرجع الرسمي
تم التحقق من وجود صفحات يقظة عامة وBMS وRSS/CAP لدى الديوان الوطني للأرصاد الجوية:
- https://www.meteo.dz/
- https://www.meteo.dz/bms
- https://www.meteo.dz/rss
تظهر الصفحات الرسمية بيانات إنذار ودرجات يقظة، لكن الموقع الرسمي يذكر قيود إعادة النشر/التوزيع دون ترخيص. لذلك المرحلة الخامسة تبدأ بروابط مباشرة ومؤشرات تنقل إلى المصدر الرسمي؛ ولا تستورد أو تعيد نشر محتوى RSS/CAP داخل Meteo DZ إلا بعد الحصول على إذن كتابي وشروط استخدام واضحة.
المراجع: https://www.meteo.dz/?lang=ar وhttps://www.meteo.dz/bms وhttps://www.meteo.dz/rss

### المناخ والزراعة: مرشح تقني لا اعتماد إنتاجي تلقائي
- Historical Weather API يقدم بيانات إعادة تحليل ERA5/ERA5-Land منذ 1940، ويجب تسميتها إعادة تحليل لا قياسات محطة مباشرة.
- Climate API يعرض إسقاطات نماذج مناخية متعددة لفترات مستقبلية، مع اختلاف توافر المتغيرات بين النماذج؛ يجب عرض اسم النموذج والمنهجية وعدم دمجها مع الرصد التاريخي في سلسلة واحدة.
- Forecast API يحتوي متغيرات مفيدة للزراعة مثل ET₀، evapotranspiration، soil moisture، soil temperature وgrowing degree days؛ لا تكفي وحدها لإعطاء توصية ري أو محصول دون معايرة محلية.
المراجع: https://open-meteo.com/en/docs/historical-weather-api وhttps://open-meteo.com/en/docs/climate-api وhttps://open-meteo.com/en/docs
